# Interview themes

Rolling synthesis across interviews. Updated after each call.

## 1. Capture is solved; triage is not

Every interviewee described capture as easy and cheap, and the step immediately
after capture as the expensive one. Nobody asked for a better way to get
information in.

Sources: [[Customer interview - Dana K]], [[Customer interview - Marco T]]

## 2. Trust cost is the real barrier to automation

For anyone with an existing filing habit, a suggestion they have to verify costs
the same as doing the filing themselves. Automation is only valuable if it is
trusted enough to go unchecked — which means precision matters far more than
recall.

Dana's abandoned tagging plugin is the clearest example: it wasn't wrong often,
it was *unspecific*, which amounts to the same thing.

## 3. Two segments, opposite needs

| | Protecting a system | Never built one |
|---|---|---|
| Example | Dana K. | Marco T. |
| Existing habit | Strong, manual | None |
| Attitude to automation | Suspicious | Eager |
| Wants | Extraction, not filing | Filing, structure |
| Risk | Feels overridden | Never forms a habit |

Designing one onboarding flow for both is probably a mistake.

## 4. Nobody asks for chat

Three of three interviewees brought up chat unprompted and dismissed it. This
does not mean chat is unused — it means it isn't what gets someone to install.
